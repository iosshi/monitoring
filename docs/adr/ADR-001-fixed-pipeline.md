# ADR-001: фиксированный ежедневный pipeline вместо агентного цикла

- **Статус:** принято для KT3
- **Дата:** 19.11.2026
- **Контекст:** проект раз в день обходит список URL, сравнивает страницу с последним снимком и отправляет аналитикам только значимые изменения. Пользовательский диалог и действия с внешними сайтами не нужны.

## Рассмотренные варианты

1. **Фиксированный pipeline**: загрузка страницы → извлечение текста → один вызов модели с предыдущим снимком → проверка схемы → сохранение снимка.
2. **Агентный цикл с инструментами**: модель сама выбирает повторные fetch/search/извлечение и управляет памятью.
3. **Правила без LLM**: diff HTML или DOM и регулярные выражения для товарных полей.

## Решение

Оставить фиксированный pipeline с одним логическим вызовом модели на товар (до трёх попыток на ошибки транспорта/формата), явной SQLite-памятью «последний успешный снимок по URL» и детерминированным HTML-diff как baseline. Список товаров выполняется до 10 workers. Страница с ошибкой, неопределённым результатом или размером текста выше лимита не меняет снимок.

## Причины отказа от альтернатив

- Агентный цикл не требуется для ежедневной однотипной проверки, добавляет переменное число вызовов, задержку и стоимость, усложняет воспроизводимость и разбор ошибок.
- Одних правил достаточно для baseline, но они реагируют на косметические изменения HTML и без специальных адаптеров не покрывают разные разметки товарных страниц. Правила остаются полезной частью ingestion/validation.

## Последствия

- Число шагов и поведение ошибок ограничены и фиксированы; воспроизводимость оценивается на одном JSONL.
- Уверенность ограничена качеством одного ответа модели и текущей HTML-страницы. При сомнении предыдущий снимок сохраняется.
- Нет истории всех снимков в production-хранилище и нет автономного восстановления от anti-bot; это остаётся задачей для дальнейшей версии.

## Что должно быть правдой, чтобы выбрать другой вариант

Перейти к агентному циклу следует только если на замороженном eval наборе конкретная многошаговая стратегия (например, повторная загрузка после неполной страницы или альтернативная ветка извлечения) устойчиво повышает recall/precision относительно текущего pipeline, а добавленные p95 latency и стоимость укладываются в KT2 бюджеты. Простого факта, что агентный фреймворк доступен, недостаточно.
